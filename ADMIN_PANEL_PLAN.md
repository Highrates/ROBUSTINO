# План реализации админ-панели ROBUSTINO

## Обзор

Админ-панель для управления контентом сайта ROBUSTINO с использованием Supabase для бэкенда и React для фронтенда.

## Технологический стек

- **Frontend**: React 18 + Vite
- **Backend**: Supabase (PostgreSQL + Auth + Storage)
- **State Management**: Zustand
- **Routing**: React Router v6
- **UI**: Tailwind CSS

## Архитектура

### 1. Аутентификация и авторизация

#### 1.1 Страница входа (`/admin/login`)
- Форма входа (email + password)
- Валидация полей
- Обработка ошибок
- Редирект на `/admin` после успешного входа
- Защита роутов (Protected Routes)

#### 1.2 Суперпользователь
- Создание через Supabase Dashboard или SQL скрипт
- Email: `admin@robustino.ru` (или настраиваемый)
- Роль: `admin` (кастомная роль в Supabase)

#### 1.3 Защита роутов
- HOC `ProtectedRoute` для обертки админ-роутов
- Проверка сессии при каждом запросе
- Автоматический редирект на `/admin/login` при отсутствии сессии

#### 1.4 Хранение состояния аутентификации
- Zustand store: `authStore.js`
- Функции: `login()`, `logout()`, `checkSession()`
- Состояние: `user`, `isAuthenticated`, `isLoading`

### 2. Управление товарами (кресла)

#### 2.1 Страница списка (`/admin/products`)
- Таблица со всеми товарами
- Фильтры: статус (draft/published), категория
- Поиск по названию
- Пагинация
- Действия: создать, редактировать, удалить, изменить статус

#### 2.2 Страница создания/редактирования (`/admin/products/new`, `/admin/products/:id/edit`)
- Форма с полями:
  - Название (обязательно)
  - Slug (автогенерация из названия, можно редактировать)
  - Описание (краткое)
  - Полное описание
  - Категория (select)
  - Статус (draft/published)
  - 3D модель (загрузка GLB файла в Storage)
  - Изображения (множественная загрузка)
  - Характеристики (JSON редактор или отдельные поля)
- Валидация
- Предпросмотр
- Сохранение в Supabase

#### 2.3 Функционал
- Загрузка файлов в Supabase Storage (bucket: `models`, `images`)
- Удаление товара с подтверждением
- Массовые действия (изменить статус нескольких товаров)

### 3. Управление статьями

#### 3.1 Страница списка (`/admin/articles`)
- Таблица со всеми статьями
- Фильтры: статус, категория, автор
- Поиск по заголовку
- Сортировка по дате публикации
- Пагинация

#### 3.2 Страница создания/редактирования (`/admin/articles/new`, `/admin/articles/:id/edit`)
- Форма с полями:
  - Заголовок (обязательно)
  - Slug (автогенерация)
  - Краткое описание (excerpt)
  - Контент (Rich Text Editor - например, React Quill или простой textarea)
  - Обложка (загрузка изображения)
  - Категория
  - Теги (multiple select)
  - Статус (draft/published)
  - Дата публикации (если published)
- Предпросмотр
- Сохранение

#### 3.3 Функционал
- Rich Text Editor для контента
- Загрузка изображений в Storage (bucket: `articles`)
- Управление тегами
- Статистика просмотров

### 4. Управление FAQ

#### 4.1 Страница списка (`/admin/faq`)
- Список всех вопросов-ответов
- Drag & Drop для изменения порядка отображения

#### 4.2 Страница создания/редактирования (`/admin/faq/new`, `/admin/faq/:id/edit`)

  - Вопрос (обязательно)
  - Ответ (обязательно, textarea)

  - Активность (checkbox)

#### 4.3 Функционал
- Drag & Drop для изменения порядка
- Быстрое переключение активности
- Массовое удаление

### 5. Управление проектами

#### 5.1 Страница списка (`/admin/projects`)
- Grid/Table с проектами
- Фильтры: дата, клиент
- Поиск по названию
- Сортировка по дате

#### 5.2 Страница создания/редактирования (`/admin/projects/new`, `/admin/projects/:id/edit`)
- Форма с полями:
  - Название проекта (обязательно)
  - Клиент
  - Описание
  - Изображения (множественная загрузка)

  - Дата проекта
- Сохранение

#### 5.3 Функционал
- Загрузка изображений в Storage (bucket: `projects`)
- Галерея изображений с возможностью удаления отдельных
- Управление порядком изображений

### 6. Управление вариантами обивки

#### 6.1 Расширение схемы БД
- Создать таблицу `upholstery_options`:
  ```sql
  CREATE TABLE upholstery_options (
    id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    name TEXT NOT NULL,
    description TEXT,
    color_code TEXT, -- HEX код цвета
    material_type TEXT, -- leather, fabric, etc
    texture_url TEXT, -- URL текстуры
    thumbnail_url TEXT, -- Миниатюра
    is_available BOOLEAN DEFAULT true,
    display_order INTEGER DEFAULT 0,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    updated_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
  );
  ```

#### 6.2 Страница списка (`/admin/upholstery`)
- Grid с вариантами обивки
- Превью цвета/текстуры
- Фильтры: тип материала, доступность
- Поиск

#### 6.3 Страница создания/редактирования (`/admin/upholstery/new`, `/admin/upholstery/:id/edit`)
- Форма с полями:
  - Название (обязательно)
  - Описание
  - Цвет (color picker + HEX код)
  - Тип материала (select)
  - Текстура (загрузка изображения)
  - Миниатюра (загрузка)
  - Доступность (checkbox)
  - Порядок отображения
- Превью цвета и текстуры

#### 6.4 Функционал
- Загрузка текстур в Storage (bucket: `images` или отдельный `upholstery`)
- Color picker для выбора цвета
- Связь с товарами (many-to-many через промежуточную таблицу)

## Безопасность

### 1. Row Level Security (RLS)
- Обновить политики в Supabase для более строгой проверки
- Создать кастомную роль `admin` в Supabase
- Политики должны проверять роль пользователя, а не просто `authenticated`

### 2. Защита роутов
- Все админ-роуты должны быть обернуты в `ProtectedRoute`
- Проверка сессии при каждом переходе
- Автоматический logout при истечении сессии

### 3. Валидация
- Валидация на клиенте (форма)
- Валидация на сервере (RLS + триггеры в БД)

### 4. Загрузка файлов
- Ограничение размера файлов
- Проверка типов файлов
- Очистка неиспользуемых файлов из Storage

- Админ-панель должна быть адаптивной (работать на планшетах)
